# 학습 노트 작성 방식

[Ray Tracing in One Weekend](https://raytracing.github.io/books/RayTracingInOneWeekend.html)를 따라 구현하면서 남기는 노트입니다.
정리본을 만들 때 AI(Claude)의 도움을 받습니다. 어디까지 제가 하고 어디부터 AI가 돕는지 아래에 구분해 두었습니다.
AI에게 주는 작업 지침은 [study-note 스킬](../.claude/skills/study-note/SKILL.md)에 그대로 공개해 두었습니다.

## 폴더 구조

```
notes/
├── README.md       이 문서
├── drafts/         chNN-draft.md: 챕터마다 제가 직접 쓴 초안 (오타, 틀린 이해도 그대로 둠)
├── thinking/       chNN-thinking.md: 질문마다 처음 생각과 정리된 결론을 남긴 사고 과정
├── src/            노트에 들어가는 이미지
└── chNN-note.md    검토를 거친 정리본
```

## 작성 순서

1. **책을 읽으면서 코드를 직접 따라 친다.**
   이해한 내용은 그 자리에서 코드 주석으로 적는다. 절 단위로 커밋한다 (예: `ch 4.1 The ray Class`).
2. **챕터가 끝나면 초안을 쓴다.** → `drafts/`
   책 내용과 제 생각을 섞어서 적는다. 모르는 건 질문형으로 그대로 기록한다.
3. **초안과 코드 주석을 AI에게 검토받는다.**
   - 책 원문과 비교해서 틀린 부분
   - 모호하게 적은 부분
   - 코드 주석에는 있는데 초안에서 빠진 내용
4. **이해가 안 되는 부분은 질문으로 파고든다.**
   답을 듣고 다시 반박하거나 되묻는 과정을 거친다. → `thinking/`
   질문마다 제가 **처음에 어떻게 생각했는지**와 **정리된 결론**을 같이 적는다.
5. **정리본을 만든다.** → `chNN-note.md`
   초안의 순서와 내용을 뼈대로 쓰고, 검토에서 나온 수정 사항과 질문에서 정리된 결론을 반영한다. 정리본에는 결론만 담고, 사고 과정은 `thinking/`에 둔다. 마크다운 서식을 정리하고 보충 설명을 붙이는 작업에는 AI의 도움을 받는다. 완성된 내용은 제가 다시 읽고 확인한다.

## 초안, 사고 과정, 정리본을 나눠 두는 이유

정리본만 있으면 제가 무엇을 이해했고 무엇을 틀렸는지가 드러나지 않습니다.
`drafts/`의 초안은 고치지 않고 그대로 둡니다. 정리본과 비교하면 제가 처음에 어떻게 이해했고, 어디가 틀렸고, 어떻게 바로잡았는지 볼 수 있습니다.
`thinking/`에는 그 사이에 거친 질문들을 남깁니다. 정리본은 복습용으로 결론만 깔끔하게 읽을 수 있게 하고, 사고 과정은 따로 볼 수 있게 분리했습니다.

### 예시: Ch 4

| 초안에서의 이해 | 검토 후 |
|---|---|
| "센서가 뷰포트, 렌즈가 카메라? 반대인듯" | 처음 생각(센서 = 뷰포트)이 맞았다. 차이는 뷰포트가 카메라 앞에 있어서 상이 뒤집히지 않는다는 점 |
| "사람이 읽기 좋다 < 압축이 안 되어 있음" | 읽기 좋은 건 ASCII 텍스트라서다. 압축이 없다는 건 파일이 큰 이유 |
| "P6로 압축" | P6는 압축이 아니라 바이너리 저장 방식 |
| "선형보간에 대한 간단 설명" (제목만 있음) | 공식과 `a` 값의 범위 변환까지 채움 |

초안 이후 질문으로 파고든 것 ([thinking/ch04-thinking.md](thinking/ch04-thinking.md)):
- 뷰포트 용어(upper_left, u/v, pixel_delta, pixel00_loc)가 왜 그렇게 정의되는지
- ray 방향을 정규화하지 않아도 되는 이유와, 방향이 필요할 때 그 자리에서 정규화한다는 것
- "정규화된 y"의 뜻과, y 범위가 -1 ~ 1인 이유(단위 벡터) vs 실제로 약 ±0.71인 이유(뷰포트)
- 정규화 때문에 배경에 가로 그라데이션이 생기는 이유

디버깅:
- 이미지가 안 열리는 문제를 AI와 같이 원인을 찾음. PowerShell 리다이렉트가 파일을 UTF-16으로 저장하는 문제였고, 렌더 루프의 행과 열 순서도 반대로 되어 있었음 → `fix render loop order to row-major` 커밋
